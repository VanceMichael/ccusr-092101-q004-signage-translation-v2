# 领域约定：规范发布与采用追踪

公共场所外语标识的译写规范按"签名发布包"发布，各责任单位按管理范围订阅、上报不含
公众身份信息的标识目录及所用版本；系统据此生成新旧差异与影响清单，经专业人员确认后
形成对具体载体的更新要求，并跟踪真实完成比例。

## 标识与引用

- 外部主体一律使用不含真实身份信息的引用编号：`unit_id`、`sign_ref`、`package_id`、
  `req_id`、`diff_id`、`batch_id`。
- 时间一律采用带偏移量的 ISO 8601 字符串，服务端以 UTC 归一化存储与比较。
- 附件只记录受控引用 `doc_ref` 或 `sha256` 摘要，不保存正文与个人信息。
- 业务事件携带来源（单位/管理员/系统）与记录时间，保留来源系统对事实的责任边界。

## 发布包

- 一个发布包按 `category`（场所类别：机场、医院、景区、道路、政务网页等）+
  `language_code`（语种）组织，含标准词条 `entries`、例外说明 `exceptions`、
  依据文件 `basis_docs`、`effective_at`（生效时间，可未来生效）。
- 同 类别+语种 内 `sequence_no` 递增并以 `prev_package_id` 串成版本链。
- 包内容经确定性 JSON 序列化（键排序、无空白）后做 HMAC-SHA256 签名；任何一方都可用
  同一主密钥（`SIGNING_SECRET`）离线复核。签名只覆盖不可变内容。
- 生命周期 `pending / active / superseded / withdrawn` 完全由 append-only 的
  `package_events`（issued、supersede、withdraw）结合 `effective_at` 推导，发布行本身
  不可变。每个事件同时记录 `recorded_at`（决定做出时刻）与 `effective_at`（效力发生
  时刻，可更晚）；新包签发即登记旧包的 supersede 决定，效力自新包生效时起。废止追加
  withdraw 事件并立即生效。
- 历史时点状态只计入"在该时点既已决定且已生效"的事件。因此一个在上位包发布前上报的
  旧标识版本，事后反查时仍判定为当时 active、合法可引用。

## 订阅与上报

- 单位注册时声明可管理的场所类别（可再限定点位）；只能订阅自身管理范围内的类别。
- 新发布向订阅单位投递通知；后订阅按语种补投当前 active 推荐包。上报引用某包即对该
  通知回执（`acked_at`），支持离线单位重连后对齐。
- 目录上报以 `(unit_id, batch_id)` 为幂等键：重复/离线重放返回首次回执，不产生新版本。
- 上报合法性校验：发布包存在且类别、语种匹配；词条在包内；**撤回包永不可引用，
  未生效包不可引用，新建标识只能引用当前推荐包**（旧包仅供历史查询）；既有标识在分批
  换版期间可继续停留在旧版。
- 采用进度只进不退：同一 `标识+语种+词条` 引用包的 `sequence_no` 不得因迟到或重复
  同步而倒退；相同 包+现场文本 的重报记为 duplicate。

## 差异、候选与更新要求

- 对新旧两包生成可复核差异：词条 `added / removed / changed`，并据此扫描仍停留在旧
  序号包上的现场最新版本形成影响清单（受影响载体、责任单位）。
- 自动分析**只能产生 `proposed` 候选**；专业人员 `confirm` 后才生成
  `update_requirements`（可携带单位承诺期限 `promised_by`），`reject` 则留痕且不生成
  要求。候选决策与要求生成均幂等。
- 现场版本推进到目标包（或更新包）时 `completed_at` 自动回填，完成情况只能来自真实
  上报，不能手工标记。

## 限时豁免

- 单位可因施工周期或历史建筑对某条更新要求申请限时豁免。
- `request / approve / expire / revoke` 全部是 append-only 决定事件：批准、到期、
  撤销都作为新事件叠加，**不覆盖原批准决定**，完整历史可追溯。
- 到期由时间判定并可通过 sweep 追加 `expire` 事件；仅 active 豁免可撤销。豁免生效期间
  该要求不计逾期、不计未完成。

## 查询与反查

- 公开查询按标识逐词条并列展示现场实际（actual）与当前推荐（recommended），以
  `aligned / differs` 明确分批换版期间的差异。
- 旧发布包始终支持历史查询，但 `usable_for_new_signs=false`，不得被新建标识下载引用。
- 任一标识版本可反查它当时合法引用的发布包及上报当时的生命周期状态
  （`was_legally_referenceable`）。
- 管理者按一条规范修订（目标发布包）看到受影响载体、责任单位、承诺期限与真实完成
  比例（`/admin/revisions/{package_id}/impact`）。
