# 领域约定

公共场所外语译写规范的发布、订阅、采用与复验按版本衔接。

## 基本约定

- 外部主体一律使用不含真实身份信息的引用编号（`unit_ref`、`sign_ref`、`source_system`、
  `decided_by` 等），标识目录与上报事件均不携带公众身份信息。
- 时间采用带偏移量的 ISO 8601 字符串，缺少偏移量一律拒绝；豁免决定等原始文书按原文
  照存（含原始偏移），不规范化改写。
- 附件只记录受控引用或 `sha256` 摘要（依据文件的 `reference` 字段）。
- 业务事件携带来源系统与事件编号，同一来源的同一事件幂等；来源系统对事实的责任边界
  由 `(source_system, event_id)` 唯一性保留。

## 发布包

- 发布包把语种、场所类别、标准词条、例外说明、依据文件、生效时间组织成一份带签名的
  负载（`canonical JSON -> sha256 -> HMAC-SHA256`，密钥来自 `RELEASE_SIGNING_SECRET`）。
- 签名负载发布后不改写；废止等生命周期动作以只追加事件（`package_events`）记录。
- 发布包在某一时刻的状态：`announced`（已发布未生效）/ `effective`（生效中）/
  `deprecated`（已废止）。当前推荐包 = 生效且未废止中修订号最大者。
- 旧版发布包继续支持历史查询下载（`purpose=history_query`），但只有当前推荐包允许
  用于新建标识（`purpose=new_sign`）。

## 订阅与上报

- 责任单位按管理范围订阅（场所类别 / 语种 / 地点前缀），订阅覆盖是上报被接收的前提。
- 上报以批次提交：`batch_key` 幂等（离线回执重发不产生重复记录），批次内事件按
  `(source_system, event_id)` 幂等，同一来源同一标识同一语种的 `seq` 只许前进，
  序列号回退的事件被拒绝——采用进度不因重复或离线同步而倒退。

## 差异、候选与整改要求

- 新包发布时自动对其祖先包计算词条差异（新增 / 修改 / 废止），并为仍引用祖先包的
  现行标识生成整改候选；候选生成幂等，迟到上报会触发补齐。
- 系统只能提出候选；专业人员确认后才生成整改要求，驳回则留痕不生成要求。候选决定
  不可更改。
- 责任单位对未结要求承诺期限；上报的新译文与要求译文一致、译文版本前进且引用包
  不落后于目标包时，自动登记完成事件并结转要求。完成只前进不后退。

## 限时豁免

- 单位可就施工周期、历史建筑等申请限时豁免；申请、批准、到期、撤销全部是只追加
  事件，任何后续决定都不覆盖原决定。
- 豁免状态由事件流派生：`applied` / `approved` / `active` / `expired` / `revoked`；
  到期先按时间派生，登记到期事件后落痕。
- 生效豁免中的标识，其未结要求在分析中单独计为 `exempted_open`，不计逾期。

## 追溯与公开查询

- 任一标识版本可反查其上报时引用的发布包及当时的合法性（`package_status_then`）。
- 公开查询并排展示当前推荐译文与现场实际译文；分批换版期间以 `transitioning`
  显式标注差异。
- 管理者按一条规范修订（发布包）看到受影响载体、责任单位、承诺期限与真实完成
  比例（`completion_ratio` 与剔除豁免后的 `adjusted_completion_ratio`）。
